# 模拟随机发牌的有解率与死局率：结果报告

票：[模拟随机发牌的有解率与死局率](../issues/02-deal-simulation.md)。脚本在 [`../sim/`](../sim/)，原始汇总在 [`../sim/results/`](../sim/results/)。术语见 [CONTEXT.md](../../../CONTEXT.md)。

## 一句话结论

**按现在的规则（只拐一次弯、开局 136 格占满），随机发牌几乎不可能玩通**：2 万局里只有 2 局有解，玩家平均翻 7 对就会遇到死局。不过，"保证有解"的牌阵可以在 1 毫秒左右生成出来；生成时调一个参数，就能在"一看就很简单"和"看起来和随机发牌一样、也难得多"之间连续调节难度。

## 方法

- **规则实现**：[`core.mjs`](../sim/core.mjs) 负责判断两张牌能否连线，[`test.mjs`](../sim/test.mjs) 里有 14 个手工测试用例，覆盖相邻、斜对角、直连、拐一次弯、拐点被占、需要拐两次弯等情况，全部通过。另外我把一局死局时的棋盘打印出来，肉眼核对过判定结果。
- **一个关键性质**：翻牌只会让空位变多，所以一对牌一旦能连上，以后就一直能连上。由此可以推出两种"安全翻牌"，做了绝不会吃亏：
  - 某种牌只剩两张，而且能连上；
  - 某种牌四张都在，而且能分成两对、两对都能连上。
- **求解器**（[`solver.mjs`](../sim/solver.mjs)）：用带记忆化的深度优先搜索。
  - 每一步先把所有安全翻牌做完，只在"这四张同牌怎么两两配对"上分叉。
  - 用乐观推算剪枝：假设所有挡路的牌最终都能被翻掉，如果在这个前提下仍有牌永远连不上，就判定无解。
  - 每局最多搜索 10 万个节点，超过就记为"超时"。
  - 找到的每一个解都会按顺序重放一遍来校验。
- **两种模拟玩家**（[`players.mjs`](../sim/players.mjs)），遇到死局就救场，一直玩到翻完：
  - **随手型**：在所有能翻的同牌对里随便挑一对。
  - **稳健型**：先做安全翻牌；没有安全翻牌时，挑"翻完之后可翻对最多"的那一对。用赖子时也挑用完后可翻对最多的那一对。这个玩家只往前看一步，真人大概介于随手型和稳健型之间，也可能比稳健型更强。
- **三种救场方式**：
  - **赖子**：用赖子翻掉一对。
  - **原地重洗**：把剩下的牌在原来的格子里随机打乱。
  - **重排成有解**：把剩下的牌在原来的格子里重新排列，并保证排出来的局面有解。
- **样本量**：有解率测了 20000 局；随机发牌上的玩家测了 10000 局；生成器测了 5 档难度，每档 3000 局。都在 Node 24 上用 15 个线程并行跑完，最长的一项不到 1 分钟。

## 1. 随机发牌的有解率

| 结果 | 局数（共 20000） |
|---|---|
| 有解 | **2**（0.01%） |
| 无解 | 19993（其中 19755 局在开局时就被乐观推算直接证明无解） |
| 超时（未知） | 5 |

随机发牌在开局时平均只有 **5.5 对**相邻的同牌可以翻，每 200 局里约有 1 局开局就一对都翻不了（10000 局中有 48 局）。

## 2. 随机发牌：多久会遇到死局

两种玩家都是 **100%** 会遇到死局。第一次遇到死局时剩下的牌数，P10/P50/P90 是 **112–114 / 122 / 130 张**，也就是说一般只翻了 3 到 12 对就卡住了。

## 3. 随机发牌：通关要救几次场

| 玩家 / 救场方式 | 救场次数：均值 / P50 / P90 / P99 / 最多 |
|---|---|
| 随手型 / 赖子 | 30.9 / 31 / 38 / 43 / 50 |
| 稳健型 / 赖子 | 15.2 / 15 / 19 / 23 / 27 |
| 随手型 / 原地重洗 | 7.2 / 7 / 9 / 12 / 16 |
| 稳健型 / 原地重洗 | 7.0 / 7 / 9 / 11 / 15 |
| 随手型 / 重排成有解 | 1.3 / 1 / 2 / 2 / 3 |
| 稳健型 / 重排成有解 | 1.0 / 1 / 1 / 2 / 2 |

可以看出：在随机发牌的前提下，靠赖子救场需要十几到三十几个，根本不现实；原地重洗平均每局要洗 7 次左右。只有"重排成有解"能把救场次数压到 1 次左右。

## 4. 保证有解的发牌

### 做法：正推法（[`generate.mjs`](../sim/generate.mjs)）

1. 先不看牌面，只看格子的位置。从满盘开始，每一步任选两个当前能连上的位置，把它们"翻掉"，并记下顺序。
2. 全部翻完后，给每一对位置分配一种牌（34 种牌各分两对）。
3. 刚才记下的顺序本身就是一条合法的翻牌顺序，所以生成的牌阵一定有解。

这个做法每次都能一次成功，不需要重试。原因是：无论剩下哪些位置，总能找到两个连得上的。

- 如果某一行或某一列里有两个以上的位置，那么其中相邻的两个可以直连。
- 如果每行每列都最多只有一个位置，那么任意两个位置都能拐一次弯连上。

3000 × 5 局生成出来的牌阵，全部通过了解的重放校验。

**没有采用的另外两种做法**：

- **倒推法**：从空棋盘开始一对一对往上放牌。理论上能得到同样的牌阵，但随机放的时候经常把最后几格堵死，试了 1000 次全部失败。
- **筛选法**：随机发牌，有解才要，没有解就重发。可是随机发牌的有解率只有万分之一，这条路不可行。

### 难度旋钮：`spread`

生成的每一步都以概率 `spread` 优先挑**不相邻**的两个位置。这个值越大，牌阵里相邻的同牌越少，看起来越像随机发牌，玩起来也越难。下表每档 3000 局；"赖子"一列指稳健型/随手型玩家用赖子救场、一直玩到通关时用掉的个数。

| spread | 相邻同牌对数 均值（P10–P90） | 随手型 遇死局 | 随手型 赖子 均值/P90/P99 | 稳健型 遇死局 | 稳健型 赖子 均值/P90/P99/最多 | 稳健型在 0/1/2/3/5 个赖子以内通关的比例 |
|---|---|---|---|---|---|---|
| 0 | 33.3（29–38） | 32% | 0.6 / 2 / 5 | 5% | 0.06 / 0 / 1 / 3 | 95% / 99% / 100% / 100% / 100% |
| 0.25 | 27.3（23–32） | 40% | 0.9 / 3 / 7 | 9% | 0.11 / 0 / 2 / 5 | 91% / 98% / 100% / 100% / 100% |
| 0.5 | 20.9（16–25） | 51% | 1.5 / 4 / 9 | 16% | 0.21 / 1 / 3 / 6 | 84% / 96% / 99% / 100% / 100% |
| 0.75 | 13.8（10–18） | 68% | 2.8 / 7 / 14 | 29% | 0.49 / 2 / 5 / 8 | 71% / 88% / 95% / 98% / 99% |
| 1 | 5.1（2–8） | 87% | 8.5 / 18 / 27 | 56% | 1.68 / 5 / 10 / 13 | 44% / 63% / 75% / 82% / 92% |

作为对照，随机发牌的相邻同牌是 **5.5** 对。所以：

- `spread = 1` 生成的牌阵，在"长相"上和随机发牌没有区别；
- `spread = 0` 生成的牌阵到处都是挨在一起的同牌，一眼就能看出是安排好的。

**生成耗时**（Node）：均值 0.35–1.1 毫秒，P99 在 8 毫秒以内，最慢一局 31 毫秒。在浏览器里生成完全没有压力，手机就算慢几倍也够用。

### 有解不等于不会卡住

牌阵一开始有解，玩家走错一步也可能变成无解，而且往往要过好几步才会真正卡住。下表是稳健型玩家翻到第 N 对时，当前局面仍然有解的比例。注意这里的"第 N 对"把用赖子翻掉的那几对也算在内。

| spread | 翻到第 10 对 | 第 25 对 | 第 40 对 | 第 55 对 |
|---|---|---|---|---|
| 0 | 100% | 100% | 99% | 96% |
| 0.5 | 98% | 98% | 94% | 87% |
| 1 | 84% | 68% | 58% | 62% |

也就是说，在 `spread = 1` 时，稳健型玩家翻到第 25 对时，**已经有三分之一的对局悄悄变成了无解**，玩家自己却还看不出来。

### 想让提示"不把人带进死局"，就得实时求解

要做到这一点，需要在当前局面上跑求解器。实测的耗时如下（Node，预算 10 万节点）：

- **中盘以后很快**：翻到第 40 对以后，P99 在 8 毫秒以内。
- **开局阶段偶尔很慢**：`spread` 在 0.5 以上时，P99 在 0.5–0.65 秒左右，最慢接近 1 秒。
- **完整牌阵会超时**：对刚生成的完整牌阵，有 1–3% 会超时。这些牌阵其实一定有解，只是求解器在预算内没找到解。

如果真的要做这种提示，就得准备一个兜底办法。比如：玩家一直还没偏离生成时那条解，就直接按那条解给提示；万一超时，就退回成"随便给一对能翻的"。

## 对「定发牌与死局策略」的含义

以下只是数据能说明的事，具体怎么定由那张票来决定：

- **"随机发牌 + 赖子救场"不可行**：每局需要 15–31 个赖子。
- **"随机发牌 + 原地重洗"能玩，但很烦**：每局平均要洗 7 次左右。
- **"随机发牌 + 卡住时重排成有解"每局大约救 1 次**：实际上相当于"开局 7 对左右以后换成一个有解的牌阵"。
- **"正推法发牌"最自然**：直接保证有解，生成成本可以忽略，而且自带难度旋钮 `spread`。剩下要决定的是：
  - 用哪一档难度，或者让玩家自己选难度；
  - 每局给几个赖子：比如 `spread = 1` 时，稳健型玩家 3 个赖子以内通关的约占 82%，5 个以内约占 92%；
  - 提示要不要做成"保证不进死局"（需要求解器，外加上面说的兜底办法）。

## 没有覆盖的部分

- 模拟玩家不是真人。真人可能比稳健型更强（会往前多看几步），也可能更弱。难度档位最终还要靠原型试玩来确认。
- 没有测"放宽规则"的情况，比如允许拐两次弯、允许连线绕到棋盘外面。用户已经选定了"只拐一次弯"，所以这部分不在本票范围内。
- 所有耗时都是在 Node（台式机）上测的，浏览器和手机上的数字没有实测。
