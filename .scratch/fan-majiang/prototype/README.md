# 牌阵界面与交互原型（用完即扔）

对应票：[牌阵界面与交互原型](../issues/04-board-ui-prototype.md)、[移动的界面原型](../issues/10-move-ui-prototype.md)

所有方案放在同一个页面上，用 `?variant=` 切换，对局状态在切换时保留。不带参数时打开 H。

- **A/B/C**：第一轮的三个界面方案，浮条的 ◀ ▶ 不再经过它们，要看就用 `?variant=A` 打开。
- **D 定稿**：用户在第一轮选定的组合。不会移动：提示只给翻牌，死局只看有没有能翻的对。
- **E/F/G**：在 D 上加「移动」的三种操作方式，给「移动的界面原型」那张票用（见下文）。
- **H 移动定稿**：用户在那张票里选的组合：G 的吸附拖动加 F 的点箭头，画线翻牌，多种配法直接点亮着的牌，提示用虚影加 ▼、默认优先给翻牌，死局用 E 的文字。完整结论见[移动的界面原型](../issues/10-move-ui-prototype.md)的 Answer。

**第一轮的结论**：用 D。它是 B 的侧栏、赖子模式、▼ 提示、死局卡片和深色牌背，加上 A 的麻将桌背景、A/C 的点错处理、C 的同牌高亮，不写素材来源；赖子模式里本来就能连上的一对按普通翻牌算。完整结论见[牌阵界面与交互原型](../issues/04-board-ui-prototype.md)的 Answer。

**视觉设计**（给[视觉设计](../issues/13-visual-design.md)用）：在 H 上用 `?skin=` 换皮肤，浮条上的下拉框或键盘 ↑ ↓ 也能切。只改长什么样，布局和交互不变。样式在 `skins.css`。

- `classic` 经典绿桌：就是原来的 H，牌身用 Front.svg（带模糊滤镜），翻掉的牌是深色牌背。
- `night` 夜雀：深色雀庄，墨绿桌面、金色数字和标记，牌身用 CSS 画、带翠绿牌背厚边，翻掉的格只剩一个淡淡的凹槽。
- `paper` 和纸：浅色极简，米白纸面、宋体墨字、朱红点缀，平面牌、细边框，翻掉的格几乎看不见。
- `candy` 糖果：明亮活泼，青紫渐变背景、圆滚滚的大按钮、橙色牌背厚边，翻掉的格是半透明的橙色牌背。

H 也按[定开局与结束流程](../issues/06-start-and-end-flow.md)补上了：侧栏的难度小字、底部的「新局」按钮和「玩法」链接、新局面板（三档加自定义滑条，吸附到刻度、不显示数值，要放弃时显示红字），以及新的胜利卡片。原型不存档，所以"第一次打开自动显示玩法"没有做，点「玩法」能看到那段文字。

## 怎么跑

```bash
node .scratch/fan-majiang/prototype/serve.mjs
```

- 电脑：<http://localhost:5179/prototype/>
- 手机：连同一个 Wi-Fi，打开终端里打印的局域网地址（一般是 `http://192.168.x.x:5179/prototype/`）。Windows 第一次运行时如果弹出防火墙提示，要允许"专用网络"。

顶上粉色边框的浮条是原型工具，不属于游戏界面：◀ ▶（或键盘 ← →）在 D、E、F、G、H 之间切换，⚙ 打开原型设置，⠿ 拖动浮条，▾ 收起。

## 移动的三种做法（E/F/G）

规则照[定移动机制](../issues/08-move-mechanic.md)：牌串沿横或竖方向滑进前方空位，可以停在任意一格；移完必须让串里一张牌和一张没动的同牌直线对上，只翻这一对；有多种配法时玩家选，不选就作废、弹回；算 1 步，一次撤回整次还原。三个方案的侧栏、选中、翻牌、赖子、▼ 提示都和 D 一样，只在下面这些地方不同：

| | E 拖动 | F 点选 | G 吸附 |
|---|---|---|---|
| 怎么开始 | 按住一张牌横着或竖着拖（拖过约 1/3 张牌宽才算拖，不然就是点） | 先点一张牌（照常选中），再点空位上的箭头 | 和 E 一样按住拖 |
| 和点牌翻牌怎么区分 | 拖 = 移动，点 = 选中 | 点牌 = 选中，点箭头 = 移动 | 拖 = 移动，点 = 选中 |
| 能停的格 | 拖动时，空位上的小点标出牌串能停的所有格 | 只标能配上的格：选中时，空位上出现箭头，标在串头到达的格 | 一按住就亮出能配上的格（箭头）；拖动时牌串只停在这些格上，跳着走 |
| 能不能配上 | 不提前显示；拖到哪格，那格能配上的一对就亮起来，连一条虚线 | 有箭头的格都能配上 | 有箭头的格都能配上；往没有箭头的方向拖，牌串被拽住、发红 |
| 配上时 | 画直线，翻成背面（和 D 翻牌一样） | 牌串滑过去，画直线，翻掉 | 不画线，那一对闪一下就翻掉 |
| 配不上时 | 松手后牌串弹回原处，侧栏说明原因 | 不会出现（只标能配上的格） | 不会出现（只停在能配上的格） |
| 多种配法 | 牌串停在新位置，可选的牌亮着、连虚线；点一张亮着的牌选那一对 | 侧栏卡片列出 ①② 按钮（带牌面），棋盘上标同样的编号 | 牌串旁边弹出气泡，点编号选一对 |
| 不选 | 点别处或按撤回：作废，牌串滑回去 | 按「取消」、点别处或按撤回：作废，牌串滑回去 | 点 ✕、点别处或按撤回：作废，牌串滑回去 |
| 提示给出一次移动 | 黄色虚线框出牌串，箭头指向目标，虚线格是要去的地方，▼ 标出会配上的一对 | ▼ 标出先点哪张，闪着的黄色箭头标出再点哪格，圈出会配上的那张 | 牌串的半透明虚影反复滑到目标处，圈出会配上的那张 |
| 死局卡片 | 没有能翻的牌，也没有能配上的移动了 | 走不动了：没有能直接翻的对，也没有能挪过去配上的牌 | 没有能翻的牌了：拖哪一串都配不上同牌 |

试玩时注意：

- 刚开局空位很少，几乎移不动。在原型设置里按「沿生成解快进 20 对」，空位就多了。
- 想看提示画成什么样，按「演示：提示一次移动」；想看多种配法怎么选，按「演示：提示一个有多种配法的移动」，再照着提示做。这两个按钮不算已用提示。
- 求解器给的提示有时是"把一整行 16 张牌挪 1 格"：前中盘的空位少，整行只空一格时，整行就是一个牌串。设置里的「提示优先给翻牌」会让求解器先试所有翻牌，都不行才给移动。

## 原型设置（⚙）

- **难度**（给[定难度三档](../issues/11-difficulty-tiers.md)用）：一根分两段的滑条，左半段调正推法的 `spread`（0→1），右半段是 `spread = 1` 再互换 0→68 对牌（`sim/generate.mjs` 的 `genSwap`）；另有 8 个预设，括号里是 09 号报告的稳健型遇死局比例。按"新开一局"生效，侧栏的新开一局沿用这个难度；可以填种子复现同一副牌阵。互换法存的是求解器找到的那条解（含移动），"在存下的解上"只认棋盘和解走完同样步数时一模一样；快进按钮会照着解做移动。
- **牌身渲染**：SVG 原样（带模糊滤镜）/ 去掉滤镜 / 先画成位图。「测渲染」会量重建棋盘的耗时和 136 张一起动时的帧率（页面在后台时浏览器会暂停动画，测不出来）。
- **白板加蓝框**、**横竖屏**（自动 / 强制横 / 强制竖）。
- **求解器**：节点预算；提示优先给翻牌；求解器测速（后台线程里测"刚发好"和会移动的稳健型模拟玩家走到第 10 / 25 / 40 步时的耗时，求解器算上移动，还会数第一步是移动的有几局）。
- **调试**：沿生成解快进 20 对、快进到剩 4 张（看胜利）；随机走到卡死（会移动，看死局提示和"已经无解"）；两个演示提示的按钮。
- **当前状态**：种子、计数、能配上的移动有几种、撤回栈里有几次移动、提示内容、最近几次求解的耗时。

## 文件

- `serve.mjs`：零依赖静态服务器，根目录是 `.scratch/fan-majiang/`，所以页面能直接 import `../sim/`。
- `game.js`：对局状态、翻牌、移动（先挪牌串、再翻选定的一对，或者作废）、撤回（每一步存一份棋盘和赤五的快照）、提示（求解器 → 生成解兜底 → 随便一对 → 随便一次移动）、往回找有解的局面。
- `board.js`：棋盘渲染、竖屏转置、连线、动画；移动用的浮层（拿起来跟手走、滑进来、提示虚影）和规则方向到屏幕方向的换算。
- `variants.js`：A/B/C/D 四个方案和方案列表。
- `move-variants.js`：E/F/G 三个方案和定稿 H（都是同一段代码换配置）。
- `switcher.js`：浮条和原型设置面板。
- `solver-worker.js`：后台线程里跑 `../sim/solver.mjs`（会移动的方案用 `moves: true`）。
- `tiles/`：FluffyStuff/riichi-mahjong-tiles 提交 `26e127b` 的 `Regular/` 全部 40 个 SVG 加 `Black/Back.svg`（CC0）。
