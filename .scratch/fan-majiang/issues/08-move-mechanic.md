# 定移动机制

Type: grilling
Status: resolved
Assignee: zhuoxuan233
Map: [翻麻将：从想法到规格书](../map.md)

## Question

用户在界面定稿之后补充了一个漏掉的玩法：没翻的牌可以沿着翻掉后留下的空位横着或竖着移动，并带上身后的牌；移过去以后，如果同一行或同一列里没有遮挡，就能翻掉一对同牌；翻过的牌会被挪到队列末尾。和用户一起把这个机制的规则问清楚：

- 哪些牌跟着走，能走几格，空位怎么变；
- 移完怎样算配上，配上几对、翻哪一对，配不上怎么办；
- 什么时候能移，和步数、撤回、赖子、死局、有解、提示怎么配合；
- 发牌和难度要不要跟着改；用什么术语。

术语见 [CONTEXT.md](../../../CONTEXT.md)。

## Answer

**加入「移动」：牌串沿横或竖方向滑进前方空位，移完必须让串里一张牌和一张没动的同牌直线对上，并翻掉这一对；随时都能移，算进"有解"。** 四轮问答里用户大多选了推荐项，只有 Q6、Q8 选了别的（下面第 4、5 条）。

1. **什么时候能移**：随时都能移，和翻牌并列。在赖子模式里开始移动，会退出赖子模式，照常算移动。
2. **牌串**：先选一个方向（上下左右）。一张未翻牌在这个方向上紧挨着至少一个空位，它连同身后紧挨着的未翻牌组成一个牌串；身后隔着空位的牌不算在内。
3. **只能整串走**（Q7 选甲），不能从中间拖开。所以一次移动动的总是一整段紧挨着的未翻牌。
   ```
   移动前   [西][南][东][  ][  ][中]
   拖东往右 2 格，西、南跟着走
   移动后   [  ][  ][西][南][东][中]
   ```
4. **怎么走、怎样算配上**：
   - 牌串沿这个方向直走，滑进前面连续的空位，中途不能拐弯。玩家可以停在任意一格，最远走到碰到未翻牌或棋盘边。前面占掉的空位挪到牌串后面。
   - 移完以后，牌串里至少有一张牌要和一张**没动的**同牌在同一行或同一列、中间没有未翻牌，也就是一条**不拐弯的连线**（Q6 选甲：只认直线，不按平时可以拐一次弯的连线算）。
   - 牌串里两张本来就挨着的同牌，移完还挨着，**不算配上**（Q18 选乙），免得借它们把整串挪到任意位置。这两张不用移动也能直接翻。
5. **只翻一对**（Q8 选丙）：
   - 只有一种配法：自动翻掉。
   - 有多种配法（几张牌都能配上，或者一张牌能配好几张）：全部高亮，让玩家选一对。
   - 玩家没选，而是点了别处或按了撤回：这次移动作废，牌串弹回原处。
6. **配不上就弹回**：一种配法都没有，这次移动不算，牌串弹回原处，不算步数。
7. **步数**：定义不变，还是本局累计翻牌的次数。一次移动正好翻一对，所以算 1 步；"一步没走错、也没撤回的一局恰好 68 步"仍然成立。
8. **撤回**：一次撤回还原整次移动：牌串回到原处，那一对翻回来。步数不减。
9. **有解、死局、赖子**：
   - 有解改为"不用赖子，靠翻牌和移动能翻到胜利"。
   - 死局改为"既没有能直接翻的同牌，也没有任何能配上的移动"。
   - 赖子规则不变，仍然是死局时的救命手段。
10. **提示**：可以给出一次移动，标出拖哪一串、往哪边、走到哪、会配上哪一对。求解器在预算内没有结果时，退回[定发牌与死局策略](03-deadlock-policy.md)里的兜底：沿生成解给一对，否则随便给一对。生成解只用翻牌，仍然成立。（补注 2026-10-11：[模拟加入移动后的有解率与求解耗时](09-move-simulation.md)发现，"沿生成解给一对"只在玩家还没移动过时成立；移动以后牌换了格，生成解对不上了，只能随便给一对。求解器在 5 万节点预算内超时的不到 0.5%，所以这个兜底很少用到。）
11. **发牌和难度**：保留正推法（发出来的牌阵不用移动也有解，加上移动只会更好过）、三档预设和自定义滑条。三档的数值等重新模拟后再调；要不要为了更难而换发牌方法，也等看了数据再定。
12. **术语**：动作叫「移动」，一起滑动的那段叫「牌串」，已写进 [CONTEXT.md](../../../CONTEXT.md)。同时改了「死局」「有解」「走错」「撤回」「提示」「步数」「空位」「赖子模式」几个词条。

**由规则推出来的几点**（问答里和用户核对过）：

- 牌串挪走后让出来的格可能打通别的牌。这些牌不算这次移动配上的，但移完以后可以照常点两张翻掉。
- 只拖一张单独的牌、它自己直线对上同牌，结果和直接翻掉这一对完全一样（这张牌一移过去就被翻掉了）。这种移动允许，只是没有额外作用。移动真正有用的地方，是被带着走的牌对上了同牌。

**对已定结论的影响**：

- [定发牌与死局策略](03-deadlock-policy.md)里，"有解"的定义、提示用的求解器、模拟数据和难度档位，都要改成把移动算进去。已在那张票里注明。
- [牌阵界面与交互原型](04-board-ui-prototype.md)定下的界面不变，拖动的交互另开票做原型。
