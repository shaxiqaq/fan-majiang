# 定难度三档和困难档的发牌办法

## Question

[模拟加入移动后的有解率与求解耗时](09-move-simulation.md)显示：加了移动以后，正推法的 `spread` 从 0 调到 1，稳健型模拟玩家卡住的比例只有 1%–15%，最难一档只相当于以前的普通。报告给了一种更难的发牌办法：正推法发好后随机互换 k 对牌，再用求解器确认有解。k 从 0 调到 68，卡住的比例从 15% 连续升到 77%，接近随机发牌；k ≥ 8 时几乎一定要用到移动才能通关。

在原型里把这些发牌办法做成可以切换的难度，和用户一起试玩，决定：

- **三档用什么**：简单、普通、困难各用什么发牌办法和数值，默认哪一档。报告的建议是 `spread` 0.75 / 1 / 1 再互换 16 对，对应稳健型卡住 6% / 15% / 51%，和以前 5% / 16% / 56% 的拉开程度相当。
- **困难档换不换发牌办法**：换成"互换 k 对"，还是留在正推法、接受最难一档只有 15% 会卡住。
- **自定义滑条怎么覆盖**：只调 `spread`，还是分两段：前半段调 `spread`，后半段调互换对数。
- **提示兜底用哪条解**：互换以后，正推法的生成解就不成立了，要改存求解器找到的、含移动的那条解。还要定"沿着这条解给下一步"在什么条件下成立。注意：正推法的生成解本身也只在玩家还没移动过时成立（见 09 号报告第 4 节最后一段）。

原型在[移动的界面原型](10-move-ui-prototype.md)定下的方案 H 上加。互换 k 对的做法见报告第 5 节（`sim/run.mjs` 的 `genSwap`），需要的话正式放进 `sim/generate.mjs`。

术语见 [CONTEXT.md](../../../CONTEXT.md)。

## Answer

**照 09 号报告的建议定：简单 `spread = 0.75`、普通 `spread = 1`、困难 `spread = 1` 再互换 16 对牌，默认普通；自定义滑条分两段；提示兜底改用开局时存下的那条解。** 原型在 [prototype/](../prototype/README.md) 的原型设置（⚙）里，滑条和预设都能直接试。用户四件事都选了推荐项。

1. **三档**（括号里是 09 号报告里会移动的稳健型 / 随手型模拟玩家遇到死局的比例）：
   - 简单：正推法 `spread = 0.75`（6% / 34%）
   - 普通：正推法 `spread = 1`（15% / 44%）
   - 困难：正推法 `spread = 1`，再随机互换 16 对不同种的牌，用带移动的求解器（预算 5 万节点）确认有解，无解或超时就重发（51% / 76%）
   - 默认普通。拉开程度和没有移动时的三档（5% / 16% / 56%）差不多。
2. **困难档换发牌办法**：换成"互换 k 对"。只用正推法的话，最难一档稳健型也只有 15% 会卡住，太简单。互换 16 对时，只靠翻牌有解的牌阵是 0%，几乎每局都要用到移动才能通关。代价是生成要跑求解器：原型实测每副 2–6 ms，09 号报告里 Node 最慢 0.2 秒，平均发 1.0 次就成。
3. **自定义滑条分两段**：滑条取值 0–2。
   - 左半段（0–1）就是正推法的 `spread`。
   - 右半段（1–2）是 `spread = 1` 再互换 `round((d − 1) × 68)` 对。
   - 三档预设是滑条上的 0.75、1 和约 1.235 三个点。
   - 最右端是互换 68 对，基本等于随机发牌（稳健型 77% 会卡住），不做比这更难的。这和[定发牌与死局策略](03-deadlock-policy.md)里"最难一端相当于随机发牌"不冲突。
4. **提示兜底用哪条解**：每副牌阵开局时存一条**存下的解**。
   - 正推法发的牌（滑条 ≤ 1）存生成解，只有翻牌。只要没移动过、翻掉的每一对都是解里的对（顺序随意），就算还在解上，兜底给解里第一对还没翻的。
   - 互换法发的牌（滑条 > 1）存求解器发牌时找到的那条解，含移动。只有当前棋盘和解走完同样步数时一模一样，才算还在解上，兜底给解里的下一步，可能是移动。不能放宽到"顺序随意"：解里有移动，翻牌顺序一变，牌串的长短和位置就跟着变，后面的移动可能做不成。
   - 两种发牌办法都一样：一旦移动过（正推法）或者偏离了解（互换法），就不能沿解兜底了，提示照旧落到"随便一对 → 随便一次移动"。撤回到解上以后又能兜底。
   - 求解器在困难档中盘很少超时，兜底只是保险（原型里把预算压到 5 个节点，才测到兜底给出移动提示）。

**规格书要照着写的几点**：

- [定存档与记忆](05-save-and-memory.md)里"存生成解"改为存这条**存下的解**（可能含移动），存档读出来以后照样能兜底。
- 存档里记的难度就是滑条值（0–2）。三档存成对应的点，读出来能认出是哪一档。
- 互换法用 [`sim/generate.mjs`](../sim/generate.mjs) 的 `genSwap`，发牌的随机数和种子同正推法，同一个种子、同一个难度发出同一副牌阵。
- 赤五在发好牌后再挑，和以前一样。

**没有测的**：困难档在手机上的发牌和求解耗时，交给[手机实测](07-phone-check.md)（原型的「求解器测速」现在会按当前难度发牌，测困难档时把难度调到困难再新开一局即可）。
