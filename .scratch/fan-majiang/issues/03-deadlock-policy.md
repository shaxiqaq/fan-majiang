# 定发牌与死局策略

Type: grilling
Status: resolved
Blocked by: 02
Map: [翻麻将：从想法到规格书](../map.md)

## Question

根据「模拟随机发牌的有解率与死局率」的数据，和用户一起决定游戏怎样处理死局：

- **发牌与死局怎么处理**：A. 发牌时就保证有解；B. 随机发牌，出现死局时自动重洗剩下的牌；B'. 随机发牌，卡住时把剩下的牌重排成有解的样子；C. 随机发牌，死局即判负或只能靠赖子救；或者几种组合。（数据显示 C 每局要 15–31 个赖子，B 每局要洗约 7 次，A 用正推法约 1ms 就能生成。）
- **难度**：正推法的 `spread` 用哪一档；是固定一档，还是让玩家选难度（比如简单/普通/困难对应不同的 `spread`）。
- **赖子每局给几次**；赖子用完后又遇到死局时怎么办。
- **局面悄悄变成无解时要不要告诉玩家**：数据表明玩家走错后，局面常常要过好几步才会真正卡死。
- **提示高亮哪一对**：随便一对能翻的，还是用求解器挑一对翻完后局面仍然有解的。后者开局阶段偶尔要 0.5–1 秒，还有 1–3% 会超时，需要定兜底办法。
- **撤回和上面这些怎么配合**：比如自动重洗之后，还能不能撤回到重洗之前。

数据见 [research/02-deal-simulation.md](../research/02-deal-simulation.md)。

术语见 [CONTEXT.md](../../../CONTEXT.md)。

## Answer

> **补注（2026-10-10）**：[定移动机制](08-move-mechanic.md)给游戏加了「移动」，下面几条要按它理解：
> - "有解"包括靠移动翻到胜利。
> - 死局还要求没有任何能配上的移动。
> - 提示用的求解器要算移动，提示也可以给出一次移动。
> - 第 2 条的三档数值和下面引用的模拟数据，都是没有移动时测的，要重测（见[模拟加入移动后的有解率与求解耗时](09-move-simulation.md)）。
>
> 其余决定（正推法发牌、三样帮助不限次数、兜底顺序、不主动提醒无解、死局主动显示）不变。
>
> **补注（2026-10-11）**：[模拟加入移动后的有解率与求解耗时](09-move-simulation.md)重测了数据，有几处要按它理解：
> - 第 2 条：三档数值的新建议，以及困难档要不要换发牌办法，交给[定难度三档和困难档的发牌办法](11-difficulty-tiers.md)。
> - 第 4 条的兜底"沿生成解给一对"和"翻掉的每一对都在生成解里的局面一定有解"，都只在玩家还没移动过时成立。移动以后牌换了格，生成解里剩下的牌位就对不上了。
> - 求解器的节点预算建议 5 万。
> - 求解器"证明无解"要做完一轮不走"安全翻牌"捷径的搜索：有移动时这条捷径会看错。

**用正推法发牌，开局一定有解；死局是玩家自己走错造成的，用撤回、赖子、提示三样帮助补救。三样都不限次数、随时可用，用了就记下来，只作参考。**

1. **发牌**：正推法（[sim/generate.mjs](../sim/generate.mjs) 的 `genForward`），开局牌阵一定有解。生成器同时返回一条解（`solution`），提示会拿它兜底。不采用随机发牌加重洗或重排：开局的牌阵大多是假的，而且撤回到重洗之前时，棋盘不知道该显示哪一副。
2. **难度**：简单、普通、困难三档预设，`spread` 分别为 0 / 0.5 / 1，默认普通。另外有一根连续滑条可以自定义，对应 `spread` 从 0 到 1，三档预设是滑条上的三个点。最难一端就是"困难"，不另做"比随机发牌还难"的生成法。三档数值等原型试玩后再调。（已由[定难度三档和困难档的发牌办法](11-difficulty-tiers.md)改定：0.75 / 1 / 1 再互换 16 对，滑条分两段。）在哪里选难度，交给开局流程去定。
3. **赖子**：不限次数，随时能用，不必等到死局。界面显示"已用赖子 N 个"。撤回一次用赖子完成的翻牌，N 减一，所以通关时 N 就是这一局最后用了几个赖子。这推翻了立图时"每局限次"的前提。
4. **提示**：去掉设置里的开关，提示按钮一直在，和撤回、赖子并列。界面显示"已用提示 N 次"，每按一次加一，撤回不减。这推翻了立图时"提示在设置里开关"的前提。
   - **高亮哪一对**：从当前局面跑求解器，找一对翻完后仍然有解的同牌（求解器找到的解的第一步）。求解器要在后台跑，不能卡界面。
   - **兜底**：求解器在预算内没有结果时，依次退回两种做法：
     - 如果玩家到目前为止翻掉的每一对，都恰好是生成解里的一对（按牌位算），就按生成解里剩下的顺序给出下一对。翻牌只会让空位变多，所以这一对一定成立。
     - 否则随便给一对能翻的。
   - **局面已经无解时**（必须由求解器证明，超时不算）：提示告诉玩家"已经无解"，并提供一键"撤回到走错之前"。具体做法是从当前局面往回找，撤回到最近一个确认有解的局面。用赖子可能把无解的局面救回有解，所以要往回逐个找，不能只看第一次走错。开局局面一定有解；翻掉的每一对都在生成解里的局面也一定有解，不用跑求解器。
5. **步数**：本局累计翻牌的次数，用赖子翻的也算，撤回不减。一步没走错、也没撤回的一局恰好是 68 步。
6. **局面悄悄变成无解时**：不主动提醒。玩家想知道，可以按提示。
7. **死局时**：主动显示一条不挡棋盘的提示（例如"没有能翻的牌了"），并附上撤回、赖子、提示三个快捷入口。死局判定只需要检查有没有能连线的同牌，不需要求解器。提示的样子交给原型去定。
8. **撤回和以上各项的关系**：不会发生重洗，所以撤回只需要照管计数：已用赖子数减一（如果撤回的是赖子翻牌），步数和已用提示数不变。

术语同步更新到了 [CONTEXT.md](../../../CONTEXT.md)：「牌阵」「赖子」「提示」「撤回」四个词条有改动，新增了「走错」「难度」「步数」三个词条。

没有覆盖的部分：浏览器和手机上的求解耗时还没有实测，已经加进「牌阵界面与交互原型」。兜底机制保证无论求解快慢，提示都能给出结果。
