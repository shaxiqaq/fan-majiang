## Question

用「找可以免费使用的日麻牌面素材」推荐的牌面，做一个粗糙但能点的网页原型（用完即扔），让用户看着决定：

- **布局**：电脑横屏 8×17 和手机竖屏 17×8 时，牌的大小、留白，手机上是否放得下、点得准。
- **选牌交互**：先点第一张高亮，再点第二张；能翻时怎样展示连线、怎样翻掉；不能翻（不是同牌，或者是同牌但连不上）时给什么反馈；怎样取消选择。
- **翻掉后的格**：显示牌背还是直接留空。注意这套素材的白板是纯白、没有蓝框，空位不能画成空白牌身，否则会和白板分不清；也可以考虑给白板加个框（CC0 允许修改）。
- **性能**：牌身 `Front.svg` / `Back.svg` 用了 SVG 模糊滤镜，136 张同时显示时在手机上会不会卡；卡的话去掉滤镜或改用 PNG。
- **按钮与信息**：提示、撤回、赖子三个按钮放在哪里（三个都不限次数、一直可用，没有开关）；用时、步数、已用赖子数、已用提示数在哪里显示；要不要在"关于"里写素材来源（CC0 不强制署名）。
- **使用赖子的流程**：先点赖子按钮再选两张，还是先选好两张再点赖子按钮。
- **提示的样子**：怎样高亮提示的那一对；局面已经无解时，"已经无解"和"撤回到走错之前"怎样显示。
- **死局提示的样子**：一条不挡棋盘的提示（比如"没有能翻的牌了"），附撤回、赖子、提示三个快捷入口，放在哪里、长什么样。
- **难度试玩**：原型里放一根 `spread` 滑条（0–1），让用户试玩后给出简单、普通、困难三档的建议值。目前的初值是 0 / 0.5 / 1。
- **求解器在手机上的耗时**：在后台线程（Web Worker）里对当前局面跑 [sim/solver.mjs](../sim/solver.mjs)，量一下电脑和手机上各要多久，再定节点预算。数据里只测过台式机上的 Node。

原型放在 `.scratch/fan-majiang/prototype/`，从本票链接过去。发牌直接用 [sim/generate.mjs](../sim/generate.mjs) 的正推法（保证有解，`spread` 调难度），连线判定用 [sim/core.mjs](../sim/core.mjs) 的 `connect`；随机发牌几乎一开局就会卡死，不适合用来试玩。提示、赖子、步数、死局各自怎么运作，已经在[定发牌与死局策略](03-deadlock-policy.md)里定好，原型照着做，只决定它们看起来什么样。

术语见 [CONTEXT.md](../../../CONTEXT.md)。

## 原型

[prototype/README.md](../prototype/README.md)：三个界面方案（A 顶栏+底栏、B 侧栏、C 全屏+浮动）放在同一个页面上，`?variant=` 切换；原型设置里有难度滑条、牌身渲染方式、白板加框、横竖屏、求解器测速。运行 `node .scratch/fan-majiang/prototype/serve.mjs`。

## Answer

**采用"D 定稿"：B 的侧栏布局，配 A 的绿色麻将桌背景、A/C 的点错处理和 C 的同牌高亮；赖子、提示、死局提示都用 B 的样子。** 原型在 [prototype/](../prototype/README.md) 的 `?variant=D`。手机上的三件事（竖屏点不点得准、牌身滤镜卡不卡、求解器耗时）暂不测，另开了[手机实测](07-phone-check.md)票。

1. **布局**：棋盘旁边一根竖栏（B），棋盘区背景是绿色麻将桌（A），竖栏用 B 的米色。竖栏从上到下：用时、步数、已用赖子、已用提示四个大数字；提示、撤回、赖子三个带图标的按钮（赖子的图标是素材里的问号牌 `Blank.svg`）；消息卡片。横屏时竖栏在右侧、约 220px 宽；竖屏时还在右侧，收窄到约 78–118px，四个数字排成一列，按钮改成图标在上、文字在下。
2. **选牌**（A/C 的点错处理，加 C 的同牌高亮，画连线）：
   - 点一张未翻牌就选中它（蓝框、略放大），同时场上其他牌变暗，只有同牌亮着。
   - 再点这张、点空位或点棋盘外：取消选中。
   - 点到不是同牌的牌：不报错，选中换到新点的这张。
   - 点到同牌且有连线：先画出连线（约 0.3 秒），再翻成背面。
   - 点到同牌但连不上：两张一起抖一下，侧栏显示"连不上"的原因，选中换到新点的这张。
3. **翻掉后的格**：显示深色牌背（素材 `Black/Back.svg`），白板不加框，两者一眼能分开。
4. **素材来源**：不写（CC0 不要求署名）。
5. **赖子**（B）：先按「赖子」进入赖子模式，按钮变紫，棋盘外圈出现紫色虚线框，侧栏写明怎么用；再点两张同牌。
   - 两张连不上：用赖子直接翻掉（紫光一闪），已用赖子加一。
   - 两张本来就能连上：当普通翻牌（画线、翻掉），**不算用了赖子**。
   - 翻掉一对后自动退出赖子模式；再按一次「赖子」也能退出；撤回也会退出。
   - 赖子模式里点到不是同牌的牌：和平时一样，选中换到新点的这张。
6. **提示**（B）：两张牌上方各出现一个上下跳动的红色 ▼，侧栏写"▼ 标出的这一对可以翻，翻完仍然有解"，一直保持到下一次翻牌或撤回。求解期间按钮文字变成"思考中"。局面已经无解时，侧栏卡片写"局面已经无解，前面有一步走错了"，附一个按钮"撤回到走错之前（退 N 步）"。
7. **死局提示**（B）：侧栏卡片写"没有能翻的牌了"，附撤回、赖子、提示三个按钮（其中「赖子」进入赖子模式），不挡棋盘。
8. **难度**：三档预设维持 `spread` = 0 / 0.5 / 1。

术语同步更新到了 [CONTEXT.md](../../../CONTEXT.md)：新增「选中」「赖子模式」，「赖子」补充"只有本来连不上的一对才算用了赖子"。

**没有定、留给别的票**：

- [手机实测](07-phone-check.md)：竖屏能不能点得准、用哪种牌身渲染（SVG 原样、去掉滤镜、先画成位图）、提示用的求解节点预算（现在是 10 万）。桌面浏览器里只测了 5 局，难度 0.5 下刚发好的牌阵求解最慢 1.8 ms，样本太少，不作依据。
- [定开局与结束流程](06-start-and-end-flow.md)：新开一局的入口、胜利画面。原型里的"再来一局"按钮和原型设置里的"新开一局"只是试玩用的，不是结论。
