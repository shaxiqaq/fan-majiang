# 模拟随机发牌的有解率与死局率

Type: task
Status: resolved
Map: [翻麻将：从想法到规格书](../map.md)

## Question

写一个模拟程序，在本游戏的规则下（8×17 牌阵、136 张、只有横竖、连线最多拐一次弯、途经的格必须是空位）跑大量随机牌阵，拿到「定发牌与死局策略」需要的数据：

1. **随机发牌的有解率**（不用赖子）。如果精确求解太慢，就给每局设时间上限，报告"有解 / 无解 / 超时未知"三类各占多少，并说明求解方法（比如带记忆化的 DFS）。
2. **普通玩家多久会遇到死局**：分别用"随机挑一对能翻的"和"简单贪心"两种策略玩，统计陷入死局的比例，以及死局时平均还剩多少张牌。
3. **需要几个赖子才能通关**：按上面两种策略玩，每遇到死局就用一次赖子，统计通关所需赖子数的分布（P50 / P90 / P99）。
4. **能不能快速生成保证有解的牌阵**：比如从空盘倒推、成对往回放牌。能否在浏览器里约 200ms 内生成？生成出来的牌阵看起来是否和随机发牌一样"乱"？难度上有没有明显差别？

## Answer

**按现在的规则，随机发牌几乎不可能玩通；但"保证有解"的牌阵可以在 1 毫秒左右生成出来，还能调难度。**

1. **有解率**：20000 局随机发牌，有解 2 局（0.01%），无解 19993 局（其中 98.8% 在开局时就被直接证明无解），超时 5 局。求解方法是带记忆化的深度优先搜索：先做完所有安全翻牌，只在"四张同牌怎么配对"上分叉，再用乐观推算剪枝。
2. **死局**：两种模拟玩家在随机发牌上都是 100% 遇到死局。第一次死局时剩余牌数的中位数是 122 张（P10–P90 为 112–130 张），也就是一般只翻了 7 对左右。
3. **通关要救几次场**（均值 / P90 / P99）：
   - 用赖子：随手型 31 / 38 / 43 个，稳健型 15 / 19 / 23 个；
   - 原地重洗：约 7 / 9 / 12 次；
   - 重排成有解：约 1 / 1–2 / 2 次。
4. **保证有解的发牌可以做**：用正推法（只看位置，从满盘开始成对翻掉，最后再分配牌种），可以证明每次都一次成功。Node 上生成一局的均值不到 1.1 毫秒，最慢 31 毫秒。参数 `spread`（0–1）是难度旋钮：
   - `spread = 0`：相邻同牌 33 对，一看就是安排好的；稳健型玩家只有 5% 会卡住。
   - `spread = 1`：相邻同牌 5 对，看上去和随机发牌一样；稳健型玩家 56% 会卡住，平均要用 1.7 个赖子，3 个以内通关的占 82%，5 个以内占 92%。
   - 另外，玩家走错后，局面往往会悄悄变成无解。`spread = 1` 时，翻到第 25 对已有约三分之一的对局无解。如果要做"保证不进死局"的提示，就需要实时求解：中盘以后不到 10 毫秒，开局阶段 P99 在 0.5–0.65 秒，对完整牌阵有 1–3% 会超时，需要准备兜底办法。
