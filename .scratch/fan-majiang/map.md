# 翻麻将：从想法到规格书

Label: wayfinder:map

## Destination

一份可以直接开工的规格书 `.scratch/fan-majiang/spec.md`：规则、交互、提示/撤回/赖子的细节、发牌与死局策略、技术选型全部定好，交给人或 agent 一口气实现成网页游戏。

## Notes

- 领域：单人网页小游戏，玩法类似连连看。术语以根目录 [CONTEXT.md](../../CONTEXT.md) 为准，每个 session 先读它；讨论中出现新术语或术语含义变了，就用 domain-modeling 技能当场更新。
- 和用户用中文交流。
- 讨论票调用 grilling + domain-modeling；原型票调用 prototype；调研票调用 research。原型和调研的产物放在 `.scratch/fan-majiang/` 下，从票里链接过去，不贴进票里。
- 立图时已定的前提：
  - 网页游戏，TypeScript + Vite，打包成静态页面；给自己和朋友小范围分享。
  - 牌阵 136 张，其中三张五是赤五（与普通五算同牌）。
  - 只有上下左右算相邻，斜对角不算；因为最多拐一次弯，连线不会绕出棋盘外。
  - 赖子是道具，不是棋盘上的百搭牌。
  - 撤回不限次数，可撤回到开局。
  - （立图时的"赖子每局限次""提示在设置里开关"已被[定发牌与死局策略](issues/03-deadlock-policy.md)推翻。）
  - 显示用时和步数，仅作参考，不排名。
  - 电脑横屏 8×17；手机竖屏时转置成 17 行 × 8 列（规则不变）。

## Decisions so far

<!-- 每张已关闭的票一行：[票名](链接)：一句话结论 -->
- [找可以免费使用的日麻牌面素材](issues/01-tile-assets.md)：用 FluffyStuff/riichi-mahjong-tiles 的 SVG（CC0 公有领域，免署名、可改、可打包），34 种 + 三张赤五 + 牌背齐全，3:4 平视，牌面需叠在 Front.svg 牌身上
- [模拟随机发牌的有解率与死局率](issues/02-deal-simulation.md)：随机发牌几乎必然无解（2/20000），平均翻 7 对就卡死；正推法可在约 1ms 内生成保证有解的牌阵，`spread` 参数从"一看就简单"连续调到"像随机发牌、稳健玩家 56% 会卡住"
- [定发牌与死局策略](issues/03-deadlock-policy.md)（有解、提示、难度数值已被「定移动机制」修改，三档数值最终由「定难度三档」定）：正推法发牌，开局一定有解；难度分三档，另有自定义滑条；赖子、提示、撤回都不限次数，赖子和提示的使用次数记下来、只作参考；提示只给翻完后仍有解的一对；局面变成无解时不主动提醒，真正卡死时才主动显示
- [牌阵界面与交互原型](issues/04-board-ui-prototype.md)：用 B 的侧栏（右侧竖栏放四个计数、提示/撤回/赖子三个按钮和消息卡片）配绿色麻将桌；选中时同牌高亮，点错就换选中，能翻先画线再翻成深色牌背；赖子先按按钮进赖子模式，本来能连上的不算用赖子；提示用 ▼ 标出；不写素材来源；难度维持 0 / 0.5 / 1。手机上的实测另开了票
- [定移动机制](issues/08-move-mechanic.md)：加入「移动」，随时都能用：牌串（一张牌和身后紧挨着的未翻牌）整串沿横或竖方向滑进前方空位，可以停在任意一格；移完必须让串里一张牌和一张没动的同牌直线对上，只翻这一对（有多种配法时玩家选），否则弹回；算 1 步，一次撤回整次还原；有解和死局都把移动算进去，提示可以给出移动；赖子保留；正推法和三档难度保留，数值重测
- [模拟加入移动后的有解率与求解耗时](issues/09-move-simulation.md)：加了移动以后游戏容易很多：随机发牌 97% 有解；最难一档稳健型只有 15% 会卡住，三档拉不开。求解器仍然够快，提示能实时求解（建议预算 5 万节点），但证明无解要多搜一轮；"沿生成解兜底"只在没移动过时成立。更难的发牌可以用"正推法再互换 k 对牌"
- [移动的界面原型](issues/10-move-ui-prototype.md)：定稿方案 H：拖动时只停在能配上的格，也可以点牌再点箭头；配上画直线再翻；多种配法直接点亮着的牌，不选就作废弹回；提示给移动时用虚影加 ▼，默认优先给翻牌；死局写「没有能翻的牌，也没有能配上的移动了」
- [定存档与记忆](issues/05-save-and-memory.md)：当前这一局（开局牌阵、生成解、整条撤回历史、四个计数、已给出的提示）完整存在本机浏览器里，打完也保留到开新局；记住上次选的难度；用时只算前台时间；不记历史战绩；存档读不出来就丢掉开新局
- [定难度三档和困难档的发牌办法](issues/11-difficulty-tiers.md)：简单 `spread` 0.75、普通 `spread` 1（默认）、困难 `spread` 1 再互换 16 对牌并用求解器确认有解；自定义滑条分两段（前半调 `spread`，后半调互换 0→68 对）；每副牌阵存一条解（互换法存求解器的含移动解）给提示兜底，互换法只在棋盘和解完全一致时才沿解兜底
- [定开局与结束流程](issues/06-start-and-end-flow.md)：打开页面直接恢复存档，没存档就直接按普通发一局并在侧栏说明玩法（之后点「玩法」能再看）；侧栏「新局」按钮弹出新局面板，选三档或自定义（不显示数值），放弃确认合并在面板里；胜利只在侧栏卡片显示成绩和难度，不挡棋盘，之后能撤回
- [定最终分享方式](issues/12-share-method.md)：挂到 GitHub Pages，公开仓库 `fan-majiang`，推到 `main` 用 Actions 自动发布；拿到链接就能玩，不做 PWA、不要自己的域名、不写许可证；原型和调研放存档分支 `prototype-archive`
- [手机实测](issues/07-phone-check.md)：iPhone 上实测，界面照方案 H 不改；求解预算维持 10 万节点（困难档最慢约 1.2 秒，没有超时）；发牌放进后台线程；牌身渲染挪到视觉设计票
- [视觉设计](issues/13-visual-design.md)：选「夜雀」：墨绿桌面、深灰侧栏、金色点缀；牌身用 CSS 画（象牙色加翠绿厚边，不用模糊滤镜）；翻掉的格只留淡淡的凹槽，不再显示牌背
